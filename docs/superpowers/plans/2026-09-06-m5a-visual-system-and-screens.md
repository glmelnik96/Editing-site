# M5a. Визуальная система и экраны вне редактора — план реализации

> **Для агентов:** ОБЯЗАТЕЛЬНЫЙ ПОД-НАВЫК: выполнять этот план задача за задачей через
> superpowers:subagent-driven-development. Шаги помечены чекбоксами (`- [ ]`).

**Цель:** гость видит одно предложение и одну кнопку, вошедший — две крупные карточки, и весь сайт говорит одним визуальным языком с соседями по ВМ.

**Архитектура:** `main.ts` худеет до сборки и маршрутизации; каждый экран — свой модуль с `mount…(el)` и `stop()`, как уже сделано для редактора и панелей. Визуальный язык живёт в `style.css` токенами и классами, без библиотеки компонентов.

**Спека:** `docs/superpowers/specs/2026-09-06-ux-redesign-and-subtitle-review-design.md`. Ниже она превращается в задачи; решения не пересматриваются.

## Что меняем и чего не трогаем

| | |
|---|---|
| Меняем | `web/src/main.ts` (разъезжается на модули), `style.css` (переписывается), появляются экраны двери, кабинета, записей, нового проекта, списка проектов, настроек |
| Не трогаем | Весь сервер, `editor.ts` и панели внутри него (это M5b), `api.ts`, `upload.ts`, `timeline/`, `strip.ts`, `player.ts`, `timecode.ts` |
| Переиспользуем | `mountAssets` (список записей), `mountProjects` (список проектов), `mountCabinet` (кабинет доступа) — их разметку перекрашиваем, логику не переписываем |

Прежние тесты vitest должны остаться зелёными: они про чистую логику, а не про разметку.

### Task 2: Оболочка и маршрутизация

**Files:** создать `web/src/shell.ts`, `web/src/router.ts`; изменить `web/src/main.ts`

- [ ] **Step 1: Маршрутизатор**

`web/src/router.ts` — чистая часть с тестами (`web/src/router.test.ts`):

```ts
export type Route =
  | { name: 'home' }
  | { name: 'files' }
  | { name: 'new' }
  | { name: 'projects' }
  | { name: 'settings' }
  | { name: 'admin' }
  | { name: 'editor'; projectId: string }

export function parseRoute(hash: string): Route
```

Тесты: `#/` и пустая строка дают `home`; `#/files`, `#/new`, `#/projects`, `#/settings`, `#/admin` — своё; `#/p/prj_1` даёт редактор с идентификатором; мусор (`#/чепуха`, `#/p/`, `#/p/../x`) даёт `home`.

- [ ] **Step 2: Оболочка**

`web/src/shell.ts` — `mountShell(root)` рисует шапку и контейнер экрана, возвращает `{ screen: HTMLElement, setUser(me), setQuota(bytes) }`.

Шапка: слева имя сервиса ссылкой на `#/`, справа занятое место, «Настройки», «Кабинет доступа» (только администратору) и «Выйти». Пустая шапка у гостя: только имя сервиса.

- [ ] **Step 3: main.ts**

`main.ts` остаётся: загрузка `/api/v1/me`, выбор экрана по маршруту, остановка предыдущего экрана, показ двери при `401`, показ ошибки иначе. Всё остальное уезжает в модули экранов. Хранить текущий экран как `{ stop?: () => void } | null` и звать `stop()` перед сменой — как сейчас делается для редактора.

- [ ] **Step 4: Прогон и коммит**

```bash
git add web/src/router.ts web/src/router.test.ts web/src/shell.ts web/src/main.ts
git commit -m "feat(web): shell and hash routing"
```
